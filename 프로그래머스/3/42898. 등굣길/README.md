## 코드

```cpp
#include <vector>
using namespace std;

int solution(int m, int n, vector<vector<int>> puddles) {
    const int MOD = 1000000007;
    int cnt[101][101] = {0,};              // 0행·0열은 패딩

    for (int i = 0; i < puddles.size(); i++)
        cnt[puddles[i][1]][puddles[i][0]] = -1;

    cnt[0][1] = 1;                         // 시작점에 1이 흘러들도록

    for (int i = 1; i <= n; i++) {
        for (int j = 1; j <= m; j++) {
            if (cnt[i][j] == -1) {         // 장애물 → 0으로 확정
                cnt[i][j] = 0;
                continue;
            }
            cnt[i][j] = (cnt[i-1][j] + cnt[i][j-1]) % MOD;
        }
    }
    return cnt[n][m];
}
```

**복잡도** — 시간 `O(m × n)`, 공간 `O(m × n)`

## 막혔던 지점

### 1. 좌표 순서가 뒤집혀 있다

`m`, `n`이 **가로, 세로** 순으로 주어진다. 보통은 세로(행) → 가로(열) 순인데 이 문제는 반대다. `puddles`의 원소도 `[x, y]` 형태라 배열에 표시할 때 인덱스를 바꿔야 한다.

```cpp
cnt[puddles[i][1]][puddles[i][0]] = -1;   // [행] = y, [열] = x
```

예제의 웅덩이가 `[2, 2]`로 대칭이라 뒤집힌 채로도 통과해서 한참 못 찾았다.

> **좌표가 대칭인 예제는 순서 검증에 쓸 수 없다.** 비대칭 입력을 직접 만들어 확인할 것.

### 2. 모듈러는 매 연산마다

경로 수는 최대 `C(198, 99)`까지 커져서 `int`는 물론 `long long`도 범위를 넘는다. 마지막에 한 번만 나머지를 취하면 이미 오버플로된 쓰레기 값을 나누는 셈이라 결과가 틀린다.

> **덧셈 결과에 모듈러를 요구하는 문제는 예외 없이 매 연산마다 적용한다.**

### 3. 조건 분기가 5갈래로 불어났다

처음엔 경계(`i==0`, `j==0`)와 장애물을 각각 따로 처리했다. 분기가 많아질수록 실수가 숨을 자리도 늘어난다. 두 가지로 정리했다.

**1-인덱스 + 패딩** — 배열을 `[101][101]`로 잡고 인덱스를 1부터 쓰면 0행·0열이 전부 0인 여유 공간이 된다. `i-1`, `j-1`이 0이 돼도 배열 밖을 나가지 않고 0을 읽는다. 배열 밖에서 오는 경로 수는 원래 0이므로 의미도 정확히 맞다. → 경계 검사가 전부 사라진다.

**장애물을 값으로 흡수** — `-1`은 "막힘"을 나타내는 표식일 뿐, 그 칸의 실제 경로 수는 **0**이다. 표식을 남겨두면 읽을 때마다 `!= -1` 검사가 붙지만, 만나는 즉시 0으로 바꾸면 이후 검사가 필요 없다.

> **"막힌 칸"과 "배열 밖"은 결국 같은 뜻이다 — 그 방향에서 오는 경로가 0개.** 특수 상태를 분기로 두지 말고 값으로 흡수시키면 코드가 짧아지고 버그도 준다.

### 시작점 초기화 트릭

`cnt[1][1] = 1`로 두고 첫 칸을 `continue`로 건너뛰는 대신, 패딩 칸인 `cnt[0][1]`에 1을 넣었다. 그러면 `(1,1)`도 일반 점화식으로 계산되고(`cnt[0][1] + cnt[1][0] = 1 + 0 = 1`), 시작점 예외 처리마저 사라진다.
