## 오답 노트

### 1. 접근 방법 자체를 못 잡았다

처음엔 "`number`보다 작은 값들을 최소 몇 개로 만들 수 있는지 저장해가며 올라간다"는 식으로 **값을 축으로** 생각했다. 하지만, 어떤 값을 만드는 모든 `(a, b)` 쌍을 찾는 비용도 크다.

문제의 **"8보다 크면 -1"** 은 단순한 예외 처리가 아니라 **DP의 축이 어디인지 알려주는 힌트**였다. 사용 횟수는 1~8로 아주 작으니 이 축으로 상태를 잡아야 한다.

> `dp[k]` = N을 정확히 k개 사용해서 만들 수 있는 모든 값의 집합

> **제약 조건이 유난히 작으면 그게 상태의 축일 가능성이 높다.**

### 2. dp[k]를 구성하는 두 갈래

N을 k개 쓴 식은 다음 둘 중 하나다.

1. `N`을 k번 이어 붙인 수 — `5`, `55`, `555`, …
2. `(i개로 만든 값) op (j개로 만든 값)` — 단 `i + j = k`

2번은 `dp[1]` ~ `dp[k-1]`이 이미 완성돼 있으므로, `i + j = k`인 모든 `(i, j)` 쌍에 대해 `dp[i] op dp[j]`를 전부 넣으면 k개짜리 식을 **빠짐없이** 표현할 수 있다. 이 확신을 갖고 들어가야 한다.

### 3. 중복 제거 — `vector` 대신 `set`

`vector`에 `push_back`만 하면 같은 값이 수없이 쌓여 크기가 수도 없이 늘어난다. `dp[8]`쯤 가면 시간초과가 난다. `set<int>`로 바꾸면 자동으로 중복이 제거되어 시간이 많이 줄어든다.

`set` 사용법도 같이 익혔다.

| 작업 | `vector` | `set` |
|---|---|---|
| 삽입 | `push_back(x)` | `insert(x)` |
| 순회 | `for (int i = 0; i < v.size(); i++) v[i]` | `for (int x : s)` |

### 4. 구현하면서 낸 실수들

- **인덱스와 값을 혼동** — `for(int icur : dp[i])`로 돌면서 정작 연산은 `i + j`로 함. 인덱스와 값의 변수명을 `i`/`icur`처럼 비슷하게 지으면 이런 실수가 잘 난다. `a`, `b`처럼 확 다르게 지을 것.
- **0 나누기 방어 위치** — `icur != jcur`로 검사했는데, 문제는 **나누는 값** `b`가 0인지다. `5/55 = 0`, `10-10 = 0`처럼 0은 실제로 생기고, 이게 나누는 수로 들어오면 C++은 에러 위치도 안 알려주고 그냥 죽는다.
- **답을 찾는 조건** — `i == number && i < answer`처럼 값(12)과 개수(100)를 비교함. k를 오름차순으로 돌고 있으니 `dp[k].count(number)`가 처음 참이 되는 순간 `return k`로 끝내면 된다. 불필요한 `dp[7]`, `dp[8]` 생성도 건너뛴다.
